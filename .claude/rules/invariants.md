## Invariants (do not break)

| Invariant | Rule |
|---|---|
| Parent owns defaults/floor | `global.agentops.runtimeDefaults` is the complete config every runtime inherits. `defaultRuntimeGuard` fails the render if nothing answers `default`. Per-route override via Pipeline (`wiring.md`) |
| No preset RBAC posture | `rbacMode` is DELETED, both levels. An account states its own rules or holds nothing. No built-in role, ever. `agentops.dev` is NEVER granted |
| Storage: operator may create, never destroy | PVC RBAC is `get`/`list`/`watch`/`create` only — no `delete`/`update`/`patch`. Created claims carry NO ownerRef on the Pipeline. Idempotent BY EXISTENCE, never patched |
| The placement rule (control vs conversations namespace) | An object lives in CONVERSATIONS if it is a runtime pod or a runtime pod runs as it, mounts it or resolves it; if it is a workload mounting a claim a runtime pod mounts (housekeeping, the context probe), or such a workload resolves it; or if it is conversation-scoped state. Nothing else moves. Equal namespace values reproduce today's single-namespace layout exactly, with no `if split` branch anywhere. `terminology.md`'s namespace pair |
| Manager reads NO secrets | Everything compiles to `valueFrom`/`envFrom` for the kubelet. `ADAPTER_TOKEN` is derived (HMAC), never minted or stored. No `secrets` RBAC verbs |
| Adapters get NO Kubernetes permissions from the operator | No RBAC, no ServiceAccount created by any reconciler. `spec.serviceAccountName` is a CHART-created reference — absent = release FLOOR |
| Strictly serial per conversation | ONE inflight unit. Two independent pools, each default 5, idle-runtime eviction per pool: `MAX_ACTIVE_CONVERSATIONS` for an uncaused conversation, `MAX_ACTIVE_MEMBERS` for a Coordinator member. `MAX_RUNTIMES` is the deprecated alias of the first |
| Cap decided before provisioning | "Active" = POD-BACKED, never status. Unadmitted → `Pending`, no pod, no `ensure-topic`. FIFO over PODS. `MAX_QUEUED_CONVERSATIONS` (50) |
| `/close` = phase, deletion is a second verb | `Closed` + `closedAt`, tears down pod/ConfigMap/slot. Object and context SURVIVE. Closed = INERT. Reopen NEVER re-resolves refs |
| `/exit` releases the runtime, `/close` ends the conversation | `/exit` deletes only the pod. REFUSED mid-run — a replacement pod would re-run completed work |
| A pod that never starts is reaped | Start DEADLINE frees the slot via the DELETE watch. Condition carries the kubelet's reason verbatim |
| One storage breaker, two edges | fed by unreachable-context reports AND provisioning failures, never two breakers. Only STORAGE-attributable failures count |
| Condition taints are not drains | Only `spec.unschedulable` + taints outside the condition set mean deliberate drain. Gated on `rbac.drainAware`, off by default |
| Housekeeping's listing is phase-blind | A CLOSED conversation still has a CR, so no phase check, or it reclaims kept state |
| Filesystem state on a PVC, else the state store | THE MANAGER MOUNTS NOTHING. The store holds conversations, `Signal`s, each source's cooldown window, its receipt counters and every adapter's own cursor. State is a cache, DERIVABLE, or declared-lossy telemetry |
| The state store has exactly two doors | the manager's own reconcilers read it DIRECTLY, through the generic contract. Every OTHER reader — the console, housekeeping — reads it through `/state/*` (`contracts.md`), never a Kubernetes watch, and holds no RBAC on a kind the store keeps |
| Conversations originate only from served sources | A channel CARRIES, never starts one. `/channel/inbound` is reply-only. No channel default profile |
| The Bot API root is the router's config, never a constant | `TELEGRAM_API_BASE`, default `https://api.telegram.org` — the router's own env var, chart-injected, never the channel adapter's (chat-ops-broker-telegram-gateway). NEVER `Channel.spec.config` |
| Every route is a dumb proxy on a non-leader, except `/healthz`, `/state/*` and `/channel/ops*` | `leaderProxyMiddleware` wraps the whole mux (chat-ops-broker-telegram-gateway, generalized from two endpoint-specific fixes). A handler reached anyway falls through to its own local behavior: `/activity*` is proxied to the leader too, serving its own local buffer only when the leader is unreachable. `/channel/ops`, its `/ack`, `/done` and `/stream` answer from ANY replica now — the command bus (`async-command-bus`) made that queue bus-backed, so the leader-only reconciler claim this row used to name is retired. NEEDS the manager's own kind admitted in its NetworkPolicy ingress rule on 8080, or every non-leader dial is silently DROPPED and the whole fix is a no-op — measured live |
| The command bus's streams and task records are a third declared bounded/lossy state home | `internal/commandbus/nats`'s one message stream and its task-record bucket, beside a PVC and the state store. An unconsumed message is kept 7 days, a succeeded task for its dedup window, dead letters 7 days or 10000. A lost bus never loses a conversation — the reconciler re-derives owed work, exactly as after any restart |
| A message type's delivery is configuration, not code | regular (competing consumers), sequential convoy (a convoy queue per key, one consumer and one message in flight, so a key runs in order and keys in parallel) or hand-over (served from the task records to an adapter over HTTP). The routing is `commandbus/nats.WithRouting`, so a new type needs one entry. `Submit` is one publish and one record write and reads from no consumer. The convoy queue controller owns convoy queue lifecycle (registry, sweep) and the convoy queue consumer controller attaches every replica to each convoy queue's shared consumer, with no lease: the server's one-message-in-flight rule is the exclusivity |
| Adapters own channel delivery: get, ack, then done or failed | `GET /channel/ops` reads without changing, `POST /channel/ops/{id}/ack` hands over and starts a per-kind delivery TTL, `POST /channel/ops/{id}/done` reports. The manager never resends an acknowledged message, a failure is final, no report by the TTL fails it. TTLs are `CHANNEL_DELIVERY_TTL_{STABLE,EPHEMERAL,TOPIC,DELETE_CONVERSATION}`. The console is the one receipt-only exception (`CHANNEL_RECEIPT_ADAPTERS`, default `console`): no TTL, no report, the manager deletes the message at the ack. A new adapter needs no manager code |
| Every thread entry has one fan-out point | `chat.FanOutThread` enqueues an input, run reply, escalation or notice to each bound channel's `out.<channel>` queue in causal order. No other path enqueues one. A channel's queue never delays another channel |
| A `202`/`200` from a converted verb means accepted, not performed | `close`, `exit`, `reopen`, `delete`, `reset-context`, `escalate` enqueue and reply before the work runs (`contracts.md#accept-and-process`). `invoke`, `/work*`, `/channel/ops*` and every read stay synchronous |
| One getUpdates consumer per bot token, ever | `gateway-telegram`, one poll loop per Deployment, one Deployment per token. A second poller produces 409s and stolen updates |
| Channel config is opaque to the operator | Never parsed manager-side. `configSchema` applies mechanically (advisory `ConfigValid` only) |
| Manager composes meaning, adapters compose presentation | No transport dialect in `internal/`. Ops carry a TYPED message, never rendered text. Adapters parse the markdown+block-grammar body, not the manager |
| A thread opens with the event that caused it | Every input delivers to every bound channel EXCEPT the one it entered on. "Already seen" is a SURFACE fact, never a message fact |
| A conversation's messages are state-store state | the run inputs on the conversation record are the permanent record, written before the input queue is pruned, whichever backend keeps them |
| No relay loops | An adapter must never re-ingest its own outbound post as inbound |
| No signal loops | An observing signal adapter must NEVER emit a signal about agent-ops' own machinery — `selfexclude.go`: name prefix, owner/label, own-namespace |
| No coordination loops | `invoke` refuses a cycle by walking `causedBy` to the root before allowing a call. NO depth limit — only a repeat is refused |
| Coordinator budgets are per-level, never pooled | `maxAgents`/`maxTurns`/`deadline` enforced on the Coordinator-root conversation alone. A caused conversation binds NO human channel — only the uncaused root does |
| Runtime pods | ownerRef → Conversation, but the manager releases pod and ConfigMap EXPLICITLY under every backend — no behaviour depends on GC. Checkout at `/data/workspace` — never move it |
| A conversation's identity is its `ID`, never its `Name` | `Name` is display, the store key and the pod name — reusable once a prior life under that name is deleted. `ID` is backend-minted, new for every life, and is what every SYSTEM reference holds: the workspace subpath, `CONVO_ID`, the pod label (`agentops.dev/conversation-id`), op ids, `causedBy.Parent` |
| Dispatch/ingest semantics | pinned by test fixtures, change deliberately |
| Signal rule vocabulary | `.claude/rules/signal-rules.md` |
