Remember: wiring lives ONLY on Pipelines — a SignalSource without a Ready
Pipeline claim drops its signals (Wired=False). Capabilities are wiring too:
AgentProfiles carry no tools and no MCP, so an agent's abilities come from the
Pipeline that originated its conversation — declared there, never inherited. A
task addresses a SOURCE and the Pipeline claiming it answers; a Pipeline that
declares no toolsets gives its conversations none.

UPGRADING FROM CHART < 3.0? Profiles no longer have spec.allowedTools or
spec.mcp; those fields are pruned on the next write. Any profile that still
relied on them is now toolless. Find them in a pre-upgrade backup, or check
which profiles have no Pipeline granting them anything:
  kubectl -n {{ .Release.Namespace }} get agentprofile -o name | while read p; do
    n=$(basename $p)
    kubectl -n {{ .Release.Namespace }} get pipeline -o jsonpath="{range .items[?(@.spec.profileRef.name=='$n')]}{.metadata.name} {end}" | grep -q . \
      || echo "no Pipeline grants capabilities to profile/$n"
  done

ACTION NEEDED — the console is exposed over plain HTTP. That token is sent as a
request header on every call, so it crosses the network in CLEAR TEXT, and it
reads every conversation payload and instructs any agent the console is joined
to. Two things to do, both worth doing:
  1. Terminate TLS. Name a certificate Secret:
       --set console.ingress.tls.secretName=<secret>
     or let cert-manager issue one:
       --set console.ingress.tls.clusterIssuer=<issuer>
     (Ignore this if TLS already terminates upstream at a load balancer or in a
     service mesh — the chart cannot see what sits in front of it.)
  2. Put an authenticating proxy in front (oauth2-proxy against your OIDC
     provider). The console reads the identity from its forwarded headers and
     logs every write with it; without one, every write is recorded as "token".
