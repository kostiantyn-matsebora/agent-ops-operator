## Context

See `proposal.md` — Why. The constraints that shape the approach:

- **The content column is fixed at `--ao-measure: 45rem` = 720px.** There is no
  breakout available: `agentops.css` records that a breakout was tried, that it
  drew the diagram under the on-this-page rail, and that "a breakout is only ever
  as wide as the column it breaks out of". So the diagram must be made to read at
  720px rather than given more room.
- **The tabbed panel set already exists** — `{: .ao-tabs}` on a markdown list,
  built by `assets/js/tabs.js`, used by `console-guide.md`. It already resolves
  the per-theme screenshot variant, deliberately, "so 'there are two themes'
  stays out of the page".
- **The six console screenshots already exist**, twelve PNGs under
  `assets/img/console/`, generated by `npm run screenshots` in `console/ui`.
- The site is a **GitHub Pages branch deploy**. No build step runs, so every
  asset the page names must be committed.
- The drawio source already carries **two** pages, `why` and `site`, and
  `export.py` exports only `site`.

## Goals / Non-Goals

**Goals:**

- Every label in the first panel legible at 720px, and on a phone.
- One tab strip, in the page, using only components that already exist.
- The diagram carries only what the prose does not.

**Non-Goals:**

- Re-generating screenshots. The console UI is unchanged.
- A responsive or stacked second diagram variant.
- Publishing the reference pages, or any other landing-page restructure.
- Touching the `why` poster.

## Decisions

### 1. A third drawio page — the poster COMPRESSED, not redesigned

`site` keeps its job: the detailed view behind the full-size link. `landing` is
the same composition made to fit: cluster panel and pill, signal column, declare
zone with its three kinds and the manifest, run zone, connectors. Only the three
blocks the page states in prose come out.

Three redesigns were drafted and rendered at the real column width first — a
Pipeline-as-hub graph, three beats with the manifest as a band, and the manifest
as the centre. All three were rejected for the same reason: a reader who knows
the poster loses the picture they already have, and the poster's composition
carries information the flatter shapes drop — chiefly *what is inside your own
cluster*, which the panel and pill state and a row of columns cannot.

*Alternative — replace `site` with the compressed drawing.* Rejected: the
detailed argument is worth keeping, and the full-size link is where a reader who
wants it goes.

### 2. Keep the poster's TYPE, compress its LAYOUT

Shrinking a drawing and simplifying one are not the same move, and only the
second buys legibility. The poster's type sizes are kept verbatim — 19px labels,
16px subtitles, 16px in the manifest — and the canvas comes down from 1778px to
**950px** by removing three blocks and tightening the rest.

SVG is vector, so what fixes on-screen size is **type ÷ canvas**. Displayed size
is `F × 720 / W`, so the 12px floor is `F ≥ W / 59`:

| Element | On the drawing | At 720px |
|---|---|---|
| Zone heading, item label | 19px | 14.4px |
| Subtitle, manifest, pill | 16px | 12.1px |

*Alternative — keep the poster and scale it down.* That is the bug this change
exists to fix: 1778px in a 720px column renders 15px labels at 6px.

### 3. Narrow viewports get a scroll frame, not a smaller diagram

At a 360px viewport the same drawing would render its labels at 6px. The panel
gets `overflow-x: auto` and the image a `min-width: 42rem`, so below the column
width the diagram **scrolls inside its own frame**. This is the pattern the
site's own responsiveness requirement already names for content that cannot
reflow, and it keeps the page body from ever scrolling horizontally.

*Alternative — a second, stacked export for narrow screens.* Rejected: a second
drawing to keep in step, for the reader most likely to open it full size anyway.

### 4. The page names ONE image; `tabs.js` resolves the variant

`paint()` in `assets/js/tabs.js` already rewrites `-light.png` → `-dark.png` on
every image inside a panel. Extend the pattern to `.png|.svg`, and extend it to
`a[href]` as well so the full-size link inside the diagram panel points at the
poster variant matching the theme.

No panel links a themed asset today — the detailed poster gets its own page in a
later change rather than a link under the diagram. The `a[href]` half of the
rewrite stays because the rule it implements is "a themed reference is resolved
by the theme", and that page will need it. It is three lines and costs a reader
nothing.

*Alternative — CSS `content: url()` keyed on `.pf-v6-theme-dark`.* It would work
without script, but replacing an `<img>`'s content drops its accessible name in
some engines, and it puts asset paths in the stylesheet. Rejected.

*Alternative — an include emitting both variants.* Rejected: it moves alt text,
which is content, into `_includes/`.

### 5. The simplified exports carry an opaque ground

Consequence of decision 4: without scripting, every reader is served the light
variant. The poster's ground is transparent, so on the dark theme its ink would
land on the dark canvas and vanish. The `landing` page therefore gets an explicit
page background per theme, and the panel styling gives it the same border and
radius the screenshots beside it already have — which also makes the strip look
like one strip.

### 6. The manifest is BOTH drawn and given as page text

It stays in the drawing, where it shows what "you declare it" means in place, and
it is also panel 2 as a fenced `yaml` block lifted from the `yb` cell unchanged.

The two are not the same artefact doing the same job: the drawn one cannot be
selected, copied, searched or read by a screen reader, and the panel one carries
no position in the picture. This is the one thing on the page that appears twice,
and it is deliberate — see the risks table.

`tabs.js`'s platform-tab pass runs first over `div[class*="language-"]`, but it
only groups **two or more adjacent** blocks with **two distinct** platform
labels, and `yaml` is not in its label map. A lone yaml block is untouched.

### 7. The strip's console panels are one line each, and link onward

The Console page owns the tour. The landing strip carries the same six views and
the same images, but **one short claim per panel** rather than the guide's
question plus explanation, and its last panel links to the Console page. Same
pictures at a different altitude, so nothing is written twice.

Labels match the guide's exactly — Overview, Topology, Conversations,
Conversation, Queues, Configuration — so a reader moving between the two pages
meets the same names.

### 7b. What it plugs into is CHIPS, grouped by the question a reader asks

A reader deciding whether this fits their stack is scanning for names, and a
sentence makes them read to find one. Three groups of chips put those names where
the eye lands.

The groups answer **questions, not packaging**: where work arrives from, what an
agent can reach, where it answers. "Which of these is in the chart" is a fact the
Installation page owns, and grouping by it made the reader translate a packaging
answer into the one they actually wanted. One consequence is load-bearing rather
than untidy: **the console appears in two groups**, because it genuinely is both
a signal source and a channel, and a group is a question rather than a list of
distinct things.

No group is coloured differently from another — the label carries the meaning,
and colouring a row would say something about it the label does not. The chips
stay quieter than the hero eyebrows above them, since a row of vendor names must
not outshout the headline it sits under.

Each chip may carry its integration's own mark, and **the page names the file**.
Putting the marks in the stylesheet would have put a vendor list in the theme,
which is the same category error as prose in a layout. Marks are committed
unaltered from each project's canonical source with their terms recorded beside
them: a mark repainted to fit this palette is no longer that project's mark.

### 8. The tiles are placed by splitting content at the first heading

Wanted order: hero → what it plugs into → strip → tiles → sections. The layout
emits the tiles at one fixed point, so it splits the page's RENDERED content on
its first `<h2>` and puts them in the seam. Everything before the page's first
section is its opening, the tiles close that opening, the sections follow.

*Alternative — a marker the page writes.* Rejected: markup in a page.

*Alternative — move the tiles into the page as a component.* Rejected for now:
the tile's inner structure (mark, value, label, note) is not something a markdown
list produces, so it would mean restyling the row from scratch to move it.

*Alternative — render `{{ content }}` before the tiles wholesale.* Rejected: that
strands the tiles at the foot of the page.

## Risks / Trade-offs

| Risk | Mitigation |
|---|---|
| A dark-theme reader fetches the light SVG, then the dark one, because `paint()` runs after parse | It is one small vector file, and only for the first panel — the rest are lazy |
| The `landing` page and the prose drift apart again as the pitch changes | The spec states the rule both ways: a claim the prose states is removed from the drawing |
| Six screenshots on the landing page make it heavy | Only panel 1 loads eagerly. `tabs.js` already marks every later panel's images `loading="lazy"` |
| `export.py` exporting two pages could silently export only one | It already fails when a page yields no single SVG. Keep that check per page |
| The strip reads as a duplicate of the Console page | Decision 7 — one line per panel and a link onward |
| The manifest is in panel 1 and panel 2 both | Deliberate (decision 6): drawn in place, and given as copyable text. If it grates, panel 2 is the one to drop — the drawing cannot be made copyable |
| The chips name Home Assistant while `ha-bundle` is still in flight | ACCEPTED by the author: that bundle is on the way and the documentation names it. The groups answer what the product does, so there is no "coming soon" slot — if the bundle slips out of the release, Home Assistant comes out of the chips in the same change |
| The `awk` prose lint or the tab strip breaks in a way markdown does not show | The docs rules require building the site and looking. That is a task, not a hope |

## Migration Plan

None. Documentation only, published by branch deploy on merge. Rollback is a
revert — the poster, its exports and the disclosure block are all still in
history, and no committed image is deleted.
