## Context

See `proposal.md` — Why. What shapes the approach:

- **`channel-telegram/render.go` already breaks on newlines.** Everything that is
  not a table is returned "untouched, line for line", so the shipped transport
  has been reading the subset this way all along.
- **The console is built on `react-markdown` + `remark-gfm`.** CommonMark makes a
  soft break a space, and nothing in `Markdown.tsx` overrides it.
- **Nothing is stored rendered.** `status.runs[].result` holds the agent's text,
  so a rendering change is not a migration.
- **The console is a released image.** A change here needs a tag, the chart
  values, and a `docs/CHANGELOG.md` entry.

## Goals / Non-Goals

**Goals:**

- One message, one shape, on every surface.
- The rule stated where the subset is defined, not in one renderer's comments.
- The author's half of the rule stated where agents read it.

**Non-Goals:**

- **A markdown flavour of our own.** The subset stays what the contract already
  names, plus the meaning of a character it never defined.
- **Reflowing or re-wrapping agent text.** A surface may wrap a long line to its
  width — that is presentation. Nothing rewrites the message.
- **Changing `format.md`'s templates.** Their shape is already right. Only the
  hard-wrapping corollary is added.

## Decisions

### `remark-breaks`, not a pre-pass over the text

The console gains the plugin, which converts soft breaks to hard breaks IN THE
AST.

- *Alternative — rewrite the string before rendering* (`text.replace(/\n/g, '  \n')`):
  it cannot see structure. Two trailing spaces inside a fenced block change the
  code, and inside a table they land in a cell. The bug would be rare, silent and
  in published output.
- *Alternative — teach agents to write blank lines between every line:* it
  re-teaches every deployed prompt to work around one renderer, doubles the
  vertical space on the transport that was already correct, and leaves the subset
  still not saying what a newline means.

### The contract changes, not just the console

Fixing `Markdown.tsx` alone would leave the next renderer free to make the same
choice. The rule goes in `adapter-rendered-messages`, where the subset lives, and
binds in-process providers too.

### Hard-wrapping becomes an authoring rule

Once a newline is a break, prose wrapped at 80 columns renders ragged. That is a
real cost and it lands on the agent, so `format.md` says it in one line — and the
screenshot fixture, which had exactly that habit, stops.

### The published assets are regenerated, not edited

Both are build output. `npm run screenshots` and `npm run demo` produce the new
shape, and the change is not done until both have run — the rule the routing
table already states.

## Risks / Trade-offs

- **An agent that hard-wraps renders ragged** → `format.md` states the rule, and
  the shipped fixture models it. Nothing enforces it mechanically, because the
  author is a language model and the surface is the only judge.
- **Existing conversations re-render** → intended, and safe: nothing is stored
  rendered, so a transcript simply looks the way it was written.
- **A new npm dependency in the console** → one small, single-purpose remark
  plugin, in a UI that already carries `react-markdown` and `remark-gfm`. The
  alternative is a string hack that corrupts code blocks.
- **The site's published assets move again** → they are regenerated by command,
  and the diff is the point: the screenshots are what proves the fix.

## Migration Plan

- **Release** — a console image tag, its value in the chart, and a
  `docs/CHANGELOG.md` entry under that version.
- **Rollback** — pin the previous console image. No data changes, so a rollback
  restores the old rendering and nothing else.
