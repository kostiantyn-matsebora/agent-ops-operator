## 1. The build gate (design D1, D7)

- [ ] 1.1 Write `.github/scripts/review-build.sh <group>`: derives the recipe from the tree per the D1 table (go.mod → `go build ./... && go vet ./...`; `platform/console` → `npm ci && npm run build` in `ui/` first; `runtimes/claude|copilot` → `node --test`; `chart` → `helm lint chart && helm template chart >/dev/null`; anything else → built), prints the recipe it chose, and on failure writes the unbuilt reading `{component, unbuilt: <last 40 lines>, findings: [], changedNames: [], files: [], threads: [], unread: [<paths>]}` to `--out` and sets `built=false` on `$GITHUB_OUTPUT`. Verify: `review-build.sh docs` prints "no build" and exits 0; a fake go module with a syntax error yields `built=false` and a reading naming the component.
- [ ] 1.2 `claude-review.yml` `read` job: conditional `setup-go` / `setup-node` / `setup-helm` on the entry's kind and group, then `id: build` running `review-build.sh` — restored from the base branch with the other read-side scripts — before any reader; the reader loop and the verdict loop (section 2) run on `steps.build.outputs.built == 'true'`, while `review-reading-check.py` runs on whichever exists, the readers' directory or the build step's reading, so the unbuilt shape is validated as any other before the upload takes it. The build step's `env` holds no secret. Verify: `.github/tests/claude-review.test.sh` asserts the build step precedes the reader loop, the script is in the restore list, and the token is on the reader and verdict steps only.

- [ ] 2.2 `review-prompt.py reader --input review-input.json --group <slug> --path <p>`: the per-file prompt — the path, `since`, the base ref, the component, the names of the component's other changed paths (carried included), the file-reading schema's shape — and `review-prompt.py reader-tools` printing the role's `tools:` line as `--allowedTools`. Verify: a re-read file's prompt carries the recorded sha as `since`, a new file's carries the base ref; the prompt holds no thread and no finding text.
- [ ] 2.3 Rewrite `.claude/agents/file-reviewer.md` as a BLIND single-file role: one file, `git diff -M <since>...HEAD -- <file>` then the file, the rules already in its context (no "read the rules" step), no threads, no verdicts; returns one file reading `{path, findings, declares, references}`. - [ ] 2.5 `claude-review.yml` `read` job: replace the component session and `review-component.js` with a shell loop — `reader-system` to a file once, then `xargs -P "$REVIEW_READERS"` (workflow variable, default 4) over the entry's paths running `claude -p "$(reader …)" --append-system-prompt "$(cat system.md)" --json-schema … --allowedTools "$(reader-tools)" --model --effort --settings`, each to `readings/<slug>/<path-slug>.json` with `|| true`; then the verdict loop the same way over paths with open threads; `review-trace.py` reads each process's stream and prints its usage — `cache_read_input_tokens` and `cache_creation_input_tokens` per process — so the job log shows the cache being hit. Verify: the workflow test asserts the loop, the variable, the system-prompt file step, that `Workflow`/`Agent(...)` appear in no `--allowedTools`, and that `review-component.js` is referenced nowhere.
- [ ] 2.6 Delete `.claude/workflows/review-component.js`; add `queue reader` and `QUEUE_READERS` to `.github/retired-vocabulary.json` with `says` naming the per-file process. - [ ] 2.7 `review-reading-check.py <dir> --group <g> --out reading.json`: merge the file readings and verdicts into the component reading — `findings`, `changedNames` (union of declares), `files`, `threads`, `unread` (every entry path with no valid file reading) — validating each file against the file schema; accept the build step's unbuilt reading (a string `unbuilt`, every list empty) as valid and reject `unbuilt` beside non-empty lists. Verify: the printed shared-prefix bytes equal the system file's size, and the per-file bytes for a re-read file are the delta's.

## 3. Coverage: recorded on the pull request (design D4)

- [ ] 3.1 `review-prompt.py coordinator --coverage <file>`: write `{"sha": headSha, "paths": {p: {"quietBefore": n}}}` from the validated readings — every `files[].path` minus `unread[]`, nothing from an unbuilt or absent component — with `quietBefore` from the queue's `quietAt`. Verify: a readings directory with one full reading, one with an unread file and one unbuilt yields exactly the read paths.
- [ ] 3.2 `review-post.py --coverage <file>`: after posting, set each path's `quiet` to `quietBefore + 1` when no inline finding was posted on it this run and to `0` when one was, and append `<!-- claude-review-coverage {"sha", "paths": {p: {"quiet": n}}} -->` as the summary's last line; a coverage file that cannot be read or serialised is an error, never a summary posted without it. Verify: a path with a posted finding records `quiet: 0`, one without records `quietBefore + 1`; a missing file fails the post with a named error.

## 4. The queue: read until quiet, then carry (design D5)

- [ ] 4.1 `review-input.py`: read the pull request's issue comments (`gh api --paginate`), take the coverage markers authored by the workflow, newest per path, into `readAt: path → sha` and `quietAt: path → n`; decide per changed path per the D5 table with `K` from `--quiet-reads` (default 1): `--full`, then rules/delta-spec invalidation (`git diff --quiet <sha> HEAD -- .claude/rules openspec/changes/<name>/specs`), then `git merge-base --is-ancestor`, then `git diff --quiet <sha> HEAD -- <path>`, then `quiet < K`; print the verdict per path with its reason. Verify: the log names every path as `read (since <sha|base>, <reason>)` or `carried (quiet n)`.
- [ ] 4.2 `review-input.json` gains `since` and `quiet` per queued path, `quietAt`, `carried: [{path, since, quiet, threads}]`, and `coverageInvalidated: "<reason>"|""`; the matrix holds only components with a read path; `queue[].paths` (the sibling list) keeps every changed path. Verify: a component whose paths are all carried produces no matrix entry; a read component's siblings include its carried paths.
- [ ] 4.3 `claude-review.yml`: `workflow_dispatch` input `full` (boolean, default false) passed as `--full`; `REVIEW_QUIET_READS` (default 1) passed as `--quiet-reads`; the queue step's summary line states reads, carried and the invalidation reason. Verify: the workflow test asserts both reach the program.
