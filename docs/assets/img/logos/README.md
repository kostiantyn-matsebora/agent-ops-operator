# Marks used in the chip set

Most of these are other projects' OWN marks, fetched from each project's canonical source
and committed unaltered. They are used **referentially** — to name an
integration agent-ops speaks to — and never to suggest endorsement.

| File | Mark | Fetched from | Terms |
|---|---|---|---|
| `kubernetes.svg` | Kubernetes | `raw.githubusercontent.com/cncf/artwork/main/projects/kubernetes/icon/color/kubernetes-icon-color.svg` | CNCF artwork, CC-BY 4.0, under the Linux Foundation trademark usage guidelines |
| `prometheus.svg` | Prometheus | `raw.githubusercontent.com/cncf/artwork/main/projects/prometheus/icon/color/prometheus-icon-color.svg` | CNCF artwork, CC-BY 4.0, under the Linux Foundation trademark usage guidelines |
| `home-assistant.svg` | Home Assistant | `raw.githubusercontent.com/home-assistant/home-assistant.io/current/source/images/favicon.svg` | Home Assistant project mark, used referentially |
| `telegram.svg` | Telegram | `telegram.org/img/t_logo.svg` | Telegram mark, used referentially |
| `mcp.svg` | Model Context Protocol | `raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/docs/favicon.svg` | MIT-licensed repository |
| `claude.svg` | Claude | `claude.ai/favicon.svg` | Anthropic mark, used referentially |

Three rules, each of which is what keeps referential use referential:

- **Do not recolour, restyle or redraw them.** A mark altered to match this
  site's palette stops being that project's mark. If one does not read on a
  ground, it is dropped rather than repainted — which is why there is no
  monochrome glyph in here.
- **The PAGE names the file, never the stylesheet.** A vendor list in
  `agentops.css` would be product knowledge in the theme, which the site's own
  invariant forbids. The chips carry ordinary markdown images.
- **Alt text is empty on purpose.** Each mark sits beside the name it belongs
  to, so announcing it again is noise to a screen reader.

**`claude.svg` names the REFERENCE RUNTIME**, not a vendor endorsement, and it is
the one chip that is not a signal source or a channel: `runtimes/claude` ships
Claude Code as the agent an install runs by default. Any runtime implementing the
work contract replaces it, which is what the chip's group label says.

- **Two canonical sources agree byte for byte** — `claude.ai/favicon.svg` and
  `raw.githubusercontent.com/anthropics/anthropic-sdk-typescript/main/.github/logo.svg`
  are the same 2558-byte file, which is how this one was confirmed to be the mark
  rather than a rendering of it.
- **It is `#D97757`, so it reads on both grounds** and needs no theme variant —
  the test every mark here has to pass, and the reason `mcp.svg` is dropped from
  the README's chip row where there is no controlled background behind it.

Re-fetch with the URLs above if a project refreshes its mark. Nothing here is
generated by a build step.

## agent-ops' own mark

`agent-ops.svg` is ours, and it is here for one reason: `_includes/logo.svg` is
drawn from `--ao-brand` and `--ao-surface`, and an `<img>` is its own document
that inherits none of the page's custom properties. So this copy states its
colours literally, and the glyph sits on the brand circle rather than on the
page — one file, readable on either ground, no theme variant.

**That makes the mark a THREE-file change**, not two:
`platform/console/ui/src/components/Logo.tsx` is the source, `_includes/logo.svg` the
masthead's copy, and this the one an `<img>` can load. Same paths in all three.
